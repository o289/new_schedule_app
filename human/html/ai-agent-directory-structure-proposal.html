Repository Structure Audit / 2026-09-15

AIエージェント向け
ディレクトリ構成提案

AIへの指示、AIが参照する資料、人間が読む資料を分離しながら、Git管理とDocker build contextの安全性を両立できるかを、現在のプロジェクト構成から評価した調査資料です。

結論

AI指示が多い：true

ルートに複数の役割文書・判断フロー・運用ルールがあり、入口から参照先が広がっています。役割ごとの責務は整理されていますが、探索負担は残ります。

人間資料とAI資料が混在：true

docs配下にHTML、計画入力、承認・品質・差分証跡が混在し、ルートにもAI向け文書があります。用途ごとの境界が見えにくい状態です。

AI資料が全部Docker対象：partly

.dockerignoreはdocsとREADME.mdを除外していますが、ルートのAI向けMD群はbuild contextに入ります。一方、最終production imageには通常残りません。dev/testではbind mountにより別の見え方になります。

推奨: AGENTS.mdは探索の入口としてルートに残し、内容の正本を`.agents/`へ集約します。人間向け資料は`docs/human/`、AIが参照する技術・運用資料は`docs/ai/context/`に分け、Dockerに不要なものはbuild contextから除外します。

6. リスクと対策

参照切れ

AGENTS探索や相対リンク、toolsの固定path、CIの参照先が壊れる。移行後に全リンク・script・workflowを検索検査する。

追跡復帰の混入

docsをGitへ戻す際、秘密・token・巨大証跡が混入する。allowlist方式とsecret scanを使う。

build破壊

必要なmigration／configを.dockerignoreで除外する。Dockerfile、compose、CIのCOPY／mount参照を先に棚卸しする。

生成物の不一致

HTMLとAI MDを手編集すると正本からずれる。plan sourceからgeneratorで生成し、hash・golden testで照合する。

7. 移行フェーズと判断事項

1

境界を決める

human／ai context／instructions／run artifactの分類、Git追跡方針、秘密の除外方針を承認。

2

配置と参照を移す

git mvで移動し、AGENTS・相互リンク・tools・generator・README・CIを更新。移行中は旧pathとの互換期間を決める。

3

Docker境界を検証

.dockerignoreとDockerfileのallowlistを確認し、dev/testのbind mountとproduction final imageを別々に検査。

4

運用を固定

generator、secret scan、リンク検査、CI artifact保存、復旧手順を品質ゲートへ追加。

判断が必要: sanitized計画をGitに保存するか、generated HTML／MDを追跡するか、runtime evidenceの保存先・期間、bind mountを個別mountへ変えるか、旧path互換をいつ廃止するかは人間が決定します。

8. 最小推奨案と厳格分離案

最小推奨案 厳格分離案
配置 AGENTS.mdを入口に残し、.agents／docs/human／docs/ai/contextだけ追加 instructions、context、source、generated、runtimeを完全分離
Docker AI資料を.dockerignoreへ追加。bind mountは維持 DockerfileのCOPY allowlist＋composeの個別mount
変更規模 中規模。リンク・ignore・CIを確認 大規模。開発体験とCI・証跡基盤も変更
評価 推奨懸念を解消しつつ過剰な階層化を避ける 将来候補秘密隔離を最優先する場合のみ
推奨判断: まず最小推奨案で用途の境界、Git追跡、build context除外を明確にします。runtimeからも隠す厳格分離は、秘密を扱うtrusted runner導入など別の承認済み計画と同時に検討します。

最終評価

現在の懸念は「AI資料が全部Dockerに残る」というより、build context・build stage・最終image・bind mountを同じ問題として扱うと誤解が生じる状態です。用途別ディレクトリと明示的なignore、generator、参照検査を導入すれば、既存のAI開発フローを維持しながら理解しやすくできます。

本資料は調査・設計のみです。アプリ、設定、既存MD、ignore、Dockerfileは変更していません。
