規模に応じて作業場所を選び、
branchに応じて公開する

版branchはpushとCI成功で完了。大規模変更の機能branchだけ、対応する版branchへ通常PRを作成します。

確定した大規模の基準

  • 5フェーズ以上
  • 変更100ファイル以上
  • 3フェーズ以上、かつ「認証変更」または「依存関係のある複数DBモデル変更」

いずれかで大規模。今回の認証変更・DBモデル変更はありません。依存のない2モデル変更だけでは3つ目の条件に該当しません。

条件 判定 作業・公開

3フェーズ + 認証変更 大規模 機能branch → 同版へのPR
3フェーズ + 依存するA/Bモデル変更 大規模 機能branch → 同版へのPR

重要変更とレビュー順序

  1. tools/pr-agent-publish.ts：旧入力を拒否しversion 2の2モードへ移行。版branchではPRコマンドを呼びません。先行・分岐remote、CI失敗、SHA不一致はSTOP。
  2. tools/pr-agent-start.ts：規模判定、cleanと開始SHAの照合。同名local/remoteを拒否し、大規模だけ機能branchを作ります。
  3. 専用テスト96件：閾値、認証と依存DBの論理和、モード不一致、再実行、CI待機・失敗、detached HEAD。
  4. 役割文書と運用例：開始記録を引き継ぎ、版branchへPR URLを要求しない規則へ統一。
公開入力version 1との暗黙互換はありません。version 2へ更新が必要です。hashは取り違え・改変の検出であり、品質証跡の真正性や分類の意味を保証する署名ではありません。
