Script Policy

scriptは「公開したいか」ではなく「再現に必要か」で分ける

scriptを確認
→
CI・品質・build・安全境界から参照?
→
YES: Git管理
PROJECT SCRIPT

Git管理する

  • package scriptから呼ばれるcheck・build・migration補助
  • CI/CDまたは品質管理から呼ばれるscript
  • DB・E2E環境を再現するrunner
  • push、PR、branch操作の安全境界
  • 上記scriptのUnit / Regression Test
  • プロジェクト固有の固定remoteやbranch規則
PERSONAL SCRIPT

Git管理しなくてよい

  • 一度限りのデータ調査・変換
  • 個人の絶対パスやローカルアプリに依存
  • 秘密情報や個人設定を含む補助script
  • 正式コマンドから参照されない試行コード
  • 生成し直せるデバッグ用snippet

非公開にする場合も、正式scriptと同じディレクトリへ混在させない。

Ignore Review

現在の.gitignore評価

現状のままでよい

  • node_modules/、.pnpm-store/：合計約992MBの再生成可能依存
  • dist/、build/、coverage/：生成物
  • .env、.env.*、鍵ファイル：秘密情報
  • backups/、dump、PostgreSQL data：ローカルデータ
  • Playwright report、test-results、E2E認証state：テスト生成物
  • IDE、OS、log、cache：端末固有または再生成可能
  • docs/*：現在の「docsはGit管理しない」方針と一致

方針を確認してから変更

  • .env.*は将来の.env.exampleも無視する
  • docs/*はHTMLだけでなく、CSS・テンプレート・設計資料・docs固有AGENTSもすべて無視する
  • 個人用scriptの専用置場はまだ定義されていない

tools/scratch/

# .env.* の後に置く（この命名で共有templateを使う場合だけ）

現在の17件を処理するための.gitignore変更は不要。上記は、今後追加する個人用scriptの置場を限定する予防策である。 現在追跡対象のtools/*を無視対象へ移す提案ではない。

Docs Trade-off

docs/*は意図的だが、再現性とのトレードオフがある

KEEP LOCAL

現方針を維持する場合

調査資料、実装計画、diff、品質証跡、レビューHTMLを公開しない目的には合っている。今回のHTMLもGit状態へ現れない。

REPRODUCIBILITY

clone先でも同じ運用をしたい場合

docs/AGENTS.md、docs/styles/、共通templateまで取得できない。将来必要になれば、生成物だけを狭くignoreし、運用資産を追跡する方針変更が必要。

現在のdocs/AGENTS.mdは「docsディレクトリのファイルをGit管理しない」と明記している。 そのため本調査ではdocs/*の解除を即時提案せず、運用の再現性を必要とする場合の別判断として扱う。
