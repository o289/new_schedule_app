調査結果から作る実装計画

AI開発フローを、個人開発に合う大きさへ

たくさんの確認画面や道具を減らしながら、「安全に作る → 検査する → branchの種類に合った公開」までAIが止まらず進めるようにします。

前提：個人開発／並列タスクなし／mainへ直接変更しない／PR #11は現在 feature/v3.2.3 にマージ済み（HEAD 0c6bac1）

1. 目的と、しないこと

目的
  • AIが計画を読み、計画内の実装を最後まで行う。
  • FAILなら直して、検査をやり直す。
  • 版branchは同名へpushしてCI確認、機能branchはpushして通常PRを作る。
  • 人は計画を最初に承認し、最後にレビューとmergeをする。
  • 安全を少ない仕組みで守る。
しないこと
  • 並列runや複数worktreeを前提にしない。
  • AI専用の別開発環境を作らない。
  • mainへのpush、force push、branch削除を許可しない。
  • 実装中に人が毎回判断する運用にしない。
  • 既存runの履歴を消さない。

2. 現状から目標へ

現在の状態 困ること 目標
canonical plan、approval、hash、期限、event log、15状態 計画だけでファイルと手順が増える 計画MD 1枚を人が承認し、[ ]を中心にする
trusted runner専用の公開経路 runnerが使えないのに直接公開も禁止され、push・PRが止まる 公開スクリプトを1つに集約し、検査後にpush・通常PRまで行う
runごとのJSON、snapshot、diff、evidenceが多数 どれが最新か分かりにくい runの引き継ぎJSONは1枚。branch/SHAはGitから読む
worktree、marker、複雑なcleanup 非並列の個人開発には重い 通常のfeature branchを作業場所にする
先に直す問題：trusted runner未実装を理由に直接公開を止める一方、直接のpushとPRも禁止するデッドロックです。Phase 1で公開経路を使える状態にします。

計画MD
→

4. 削除・統合・維持するもの

分類 対象 方針
削除候補 .agents/tools/trusted-runner/**、.agents/tools/pr-agent-publish* 単一publishへ置換後、rgで参照ゼロを確認して削除する。
削除候補 .agents/tools/agent-run/canonical-*、state-*、orchestrator*、cleanup*、legacy-import*、agent-run-command* 新方式で不要になった後、rgで参照ゼロを確認して削除する。
削除候補 global snapshot、phase log、重複diff/evidence JSON 1枚と計画MD 1枚へまとめる。
統合 重複する役割MD、package.jsonのrules:check、agent:plan:generate、agent:run、trusted-runner:check等 参照ゼロを確認後、短いAGENTS.md、計画MD、JSON、verify、publishへ整理する。
維持 feature制限、main保護、force push禁止、typecheck/test 安全の中心としてプログラムで強制する。
維持 ローカルDB限定、秘密情報保護、CI確認 本番事故と秘密漏えいを防ぐ。

5. 最小のデータと書き方

JSONは引き継ぎ用ホワイトボード

AI交代時に最初に読むメモです。branch名とSHAは正本ではなく、必要な時にGitで読み直します。 

{
  "runId": "20260917-example",
  "goal": "招待リンクを追加する",
  "currentPhase": 1,
  "nextAction": "typecheckを実行する",
  "lastVerification": "pending",
  "blocker": null,
  "updatedAt": "2026-09-17T12:00:00+09:00"
}

MDはチェックリスト

人が読む計画を1枚にします。終わったらAIが[x]にします。 

## Phase 1：APIを作る
- [ ] apps/backend/...を変更
- [ ] 招待確認処理を追加
- [ ] typecheck PASS
- [ ] test PASS
- [ ] feature branchへpush
- [ ] 版branchなら同一SHAのCI確認
- [ ] 機能branchなら通常PR作成

計画外の変更だけREPLANし、計画MDを再承認します。

6. AIが決めること／プログラムが止めること

AIに残す判断 プログラムで強制する最小ルール
仕様、変更ファイル、DB・依存・API・権限、テスト、Phase順 差分が計画外ならREPLANで停止
小規模/大規模、FAIL原因、修正方法、PR本文 agent:publish自身が同じ実行内でpnpm verify:phaseを実行し、PASSするまで公開しない（別のPASS状態ファイルを作らない）
migrationのタイミング（承認済みの場合） 本番URL・資格情報を拒否し、ローカルDBだけ許可
人へ相談する仕様判断 main操作、force push、branch削除、任意shell、秘密値出力を禁止

8. 互換性・rollback

旧履歴

ai/runs/**とdocs/agent-runs/**の両方を削除せずread-onlyで残します。新方式の正本にはしません。

戻し方

各Phaseを小さなcommitにし、FAIL時はそのPhaseをrevertします。main、remote、本番DBは変更しません。

切り替え

Phase 1の公開成功とPhase 2の引き継ぎ成功まで旧ツールを削除せず、Phase 3で参照ゼロを確認してから整理します。

9. リスクと対策

リスク 対策
mainを変更する branch名を検査し、main/releaseへのpushとforce pushを拒否。
計画外のDB/API変更 計画MDに先に書き、差分があればREPLAN。
verifyなしでPR publish自身が同じ実行でpnpm verify:phaseを実行し、PASS時だけpush/PRを行う。
履歴や秘密の漏えい ai/runs/**とdocs/agent-runs/**を保持し、秘密値をAI・JSON・ログ・PRへ出さない。

10. 最終受入条件

  • - [ ] 新規runが計画MD 1枚・JSON 1枚で開始できる
  • - [ ] 計画承認後は計画内Phaseを追加承認なしで進められる
  • - [ ] FAILは修正して再検査、計画外はREPLANで停止する
  • - [ ] agent:publish自身がverifyし、PASS時だけ公開する
  • - [ ] feature/vX.Y.Zは同名originへpushし同一SHA CI確認で完了（PR不要）
  • - [ ] feature/<slug>-vX.Y.Zはpushし版branch向け通常PR作成で完了
  • - [ ] main、force push、branch削除、本番DB、任意shellが拒否される
  • - [ ] 完了報告に必要なCI結果または通常PR URLと検証SHAがある
  • - [ ] 人はPRレビューとmergeだけを担当できる
