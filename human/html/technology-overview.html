Schedule Management App / Technology Map

フロントエンド・バックエンド技術紹介

このプロジェクトは、TypeScriptを共通言語にして、ブラウザの操作体験とAPI・データ永続化を分離しています。各技術の役割、メリット、採用理由を対応づけて整理しました。

全体アーキテクチャ

Reactが画面を構築し、HonoのAPIが認証・予定・カテゴリを処理します。packagesのスキーマは両者の契約を共有します。

採用技術と採用理由

「何ができるか」だけでなく、このスケジュール管理アプリにどう効くかをまとめています。

領域 技術 メリット このプロジェクトでの採用理由
UI React 状態を持つ画面をコンポーネント単位で分割できる カレンダー、予定カード、入力フォーム、認証状態を再利用しやすくするため
UI部品 MUI Tailwind CSS MUIはアクセシブルな部品、Tailwindは細かなレイアウト調整に強い アイコン・ボタンの品質と、PC／モバイルのレスポンシブ調整を両立するため
カレンダー FullCalendar 月・週・日表示、イベント配置などの複雑なUIを活用できる 予定管理の中心機能を安定したライブラリ上で拡張するため
データ取得 TanStack Query APIデータの取得・キャッシュ・再取得・状態管理を共通化できる 予定やカテゴリの取得状態を管理し、画面間でのキャッシュ共有と更新処理を安定させるため
API Hono 軽量でTypeScriptとの相性がよく、ルーティングとMiddlewareを簡潔に書ける 認証、CORS、キャッシュ制御、APIエラー処理を小さな構成で組み立てるため
検証 Zod 実行時に外部入力を検証し、その結果から型も導ける 環境変数・リクエスト・共有スキーマを同じ考え方で安全に扱うため
DBアクセス Drizzle ORM SQLに近い型安全なクエリとスキーマ管理ができる 予定・カテゴリ・ユーザーの関係をTypeScriptの型とMigrationで管理するため
DB PostgreSQL / pg トランザクション、制約、リレーションを堅牢に扱える ユーザー、予定、共有範囲など整合性が重要なデータを保存するため
認証 WebAuthn jose パスキーによる安全な認証とJWT処理を実装できる パスワード依存を減らし、WebAuthnのCredentialをサーバーで検証するため
Build Vite Node.js 開発サーバーが速く、フロント／バックエンドを同じ構成でBundleできる 開発時は高速なHMR、本番は軽量なdist実行に分けるため
品質 Vitest TypeScript 型チェックと高速なユニット・APIテストを一体化できる 共通言語による開発の調整コストを減らし、CIで品質ゲートを作るため

技術が連携する流れ

予定の登録を例に、画面からDBまでの責務を追います。

01 / 操作

React + MUI

フォーム入力、日時選択、カテゴリ選択を画面として提供。

02 / 通信

fetch / Router

フロントからAPIエンドポイントへリクエスト。

03 / 検証

Hono + Zod

認証状態と入力値を検証し、サービス処理へ渡す。

04 / 永続化

Drizzle + PostgreSQL

型安全なクエリと制約のもとで予定を保存。

05 / 表示

FullCalendar

APIレスポンスをイベントへ変換し、カレンダーに反映。

設計上のポイント: UIの都合をDBへ直接持ち込まず、共有スキーマを境界にしてフロントとバックエンドを接続します。

この構成のメリット

一貫性

TypeScriptを共通言語にする

画面・API・DBアクセスの型を同じ開発体験で扱え、別言語間の変換コストを抑えられます。

安全性

共有スキーマ + 実行時検証

コンパイル時の型だけに頼らず、ブラウザや環境変数から来る値もZodで検証できます。

開発速度

React + Vite + Hono

フロントのHMR、軽量なAPI、共通のTypeScript設定により、機能追加と確認を短いサイクルで回せます。

保守性

機能単位のBackend構成

auth、schedule、categoryなどをrouter・service・repositoryに分け、変更範囲を見通しやすくしています。
