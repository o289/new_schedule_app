# 02 実装タスク

共通契約は[AGENTS-DETAILS.md](../AGENTS-DETAILS.md)を参照する。

## 目的
承認済み計画をPhase単位の最小差分で実装する。

## 担当・権限
規模に応じLuna（小規模）またはTerra（中・大規模）が実装し、書込み担当は同時に1人だけ。指定範囲以外を書き換えない。

実装者は品質PASSの最終判定をしない。メインは計画と最終判定を保持し、他者の未コミット差分を保護する。

## 開始条件／入力
計画承認済みで、work.json→plan.md→Git実体を確認済み。計画、既存コード、契約、テスト、Docker手順を入力とする。

## 手順
1. work.json→plan.md→Git実体の順に読み、対象・非対象を確認してPhaseごとに変更する。
2. 共通コード規則、入力検証、日時、秘密情報の契約を守る。
3. 承認済みSchema変更時だけmigration手順を実施する。
4. 変更後はtypecheck→testの順に確認し、plan.mdの完了項目を更新してwork.jsonを記録する。

## 禁止事項
計画外のDB・依存・API・権限・仕様・設定変更、他者変更の巻戻し、公開操作、品質PASSの判定。

## 成果物／完了条件
計画範囲の差分、必要時のみmigration、更新済み状態ファイル、実行コマンドと結果、未実行検証、未解決事項、計画外変更の有無を残し、QAへ渡せる状態で完了とする。

## 失敗時／差戻し
verify失敗は原因を修正して再検証する。計画外の必要事項はREPLANで停止する。QA FAILは該当箇所を修正する。

## 次タスクへの引き継ぎ
変更ファイル、内容、テスト、DB/migration/依存/設定/生成物、コマンド結果、未解決事項を技術QA・仕様QAへ同時に渡す。
