# レビュータスク

共通契約は[AGENTS-DETAILS.md](../AGENTS-DETAILS.md)を参照する。

## 目的

変更をタスクごとに分けた人間向けdiff資料を作り、変更理由・計画・検証結果を追える形で人間の最終レビューへ渡す。

## 担当・権限

担当はレビュー資料作成者。実際のレビュー、承認、merge、merge後監視は人間が行う。レビュー資料作成は修正を含めない。指摘対応はメインから別途指定された場合に限り、承認計画内で行う。

## 開始条件／入力

公開結果、現在のGit diff、承認済み人間向けHTMLとAI向けMarkdown計画、QA/verify記録、未解決事項。PRがあればURLとhead/base/SHA、version branchならbranch・SHA・CI結果。

## 手順

1. Git差分を実装タスク/責務ごとに分類し、全差分に分類があることを確認する。
2. 各タスクについて変更ファイル、変更内容、変更理由、関連計画の受入条件、検証結果を対応付ける。
3. 技術QA・仕様QA、Docker正式verify、必要なE2Eの結果と、未実行検証・未解決事項を記載する。
4. 原差分へ辿れるリンクを含む人間向けdiff資料をhuman/html/へ作成する。
5. 資料と差分の一致を確認し、人間へ最終レビューを依頼する。

## 禁止事項

- 差分を隠す、分類漏れを残す、計画や証跡と異なる説明をすること
- QA/verify実施や人間承認をAIが代行したと表現すること
- merge、公開後監視、未依頼の製品修正を行うこと

## 成果物／完了条件

タスク別の変更内容・理由、関連計画、検証結果、未解決事項を記したdiff資料。全差分が分類され、人間が最終レビューできる。

## 失敗時／差戻し

公開結果・差分・QA証跡が不足または不一致ならPR作成/QA担当へ戻す。未承認変更や新しい仕様判断が必要なら停止し、計画書作成へ戻す。

## 次タスクへの引き継ぎ

diff資料、公開結果、未解決事項を人間へ渡す。人間レビュー、承認、merge、merge後監視をAIの完了条件にしない。
