# UIモック画像作成タスク

共通契約は[AGENTS-DETAILS.md](../AGENTS-DETAILS.md)、呼出条件は[human-plan-task.md](human-plan-task.md)を参照する。

## 目的

新規UI機能を計画承認する前に、既存UIに沿う再現可能なPNGと実装条件を用意する。

## 実行条件

新規機能開発かつ新しい画面、領域、ダイアログ、フォームなどのUI実装が必要な場合だけ実行する。既存UIの文言修正、色や余白のみの変更、バックエンドだけの変更では実行しない。

## 担当・権限

計画担当のメインが要否と最終内容を判断する。画像作成は指定された書き込み担当へ委譲できる。Mock作成時に製品コード、DB、依存、API、権限、設定を変更しない。

## 開始条件／入力

新規UIの要求、対象操作、既存画面/component/library、theme/token、素材、表示幅。詳細が未決定なら人間向け計画書作成へ戻す。

## 手順

1. package.json、対象画面のimport、実際に使われているcomponent、theme/token、素材と利用条件、対象viewportを調査する。
2. 依存に存在するだけで実際には使われていないlibraryは採用しない。Mock用の依存を追加しない。
3. 利用開始から完了までの画面、状態、操作と操作直後の表示を洗い出す。
4. 使用部品、文言、並び、寸法、余白、色、文字、状態、操作、表示幅を明記してMockを作る。
5. 必要な状態・表示幅をPNGに出力し、`human/images/mock-<feature>-<viewport>-<state>.png` を基本名とする。
6. PNGと、画像で表せない遷移や再現条件を人間向けHTML計画書に反映する。

## 禁止事項

- 新しいlibrary/依存、未使用component、未確認tokenを前提にすること
- 製品コード、DB、API、権限、設定の変更やMockの製品UIへの組み込み
- PNGにない動作を実装担当の推測に任せること
- 秘密情報、実在個人情報、本番データを含めること

## 成果物／完了条件

必要な状態・viewportを示すPNGと再現条件が人間向けHTMLから参照され、実装者が既存部品で再現できる。

## 失敗時／差戻し

既存部品だけで実現できない、UI仕様が未決定、状態が不足、または新しい依存・仕様変更が必要なら計画担当へ戻す。人間向け計画を更新し、承認前に解決する。

## 次タスクへの引き継ぎ

PNGの相対パス、使用部品、再現条件、状態とviewportを計画書へ渡し、承認後は[計画書読み取り](plan-reading-task.md)と[コード生成](code-generation-task.md)へ共有する。
