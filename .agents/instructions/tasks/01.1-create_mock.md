# 01.1 Mock UI作成タスク

共通契約は[AGENTS-DETAILS.md](../AGENTS-DETAILS.md)、呼出条件と計画への反映方法は[01 計画書作成](01-planning.md)を参照する。

## 目的

新規機能のUIを実装する前に、プロジェクトの既存UIと同じ部品・見た目で再現可能なMock UIをPNGとして作り、人間が計画と一緒に確認できるようにする。

## 実行条件

次の両方を満たす場合だけ実行する。

- 新規機能開発である
- フロントエンドに新しい画面、領域、ダイアログ、フォームなどのUI実装が必要である

既存UIの文言修正、色や余白だけの変更、バックエンドだけの変更では実行しない。判断できない場合は、計画担当のメインが既存コードを調べて決める。

## 担当・権限

計画担当のメインが実行条件と最終内容を判断する。Mockの作成作業は書き込み担当1人へ委譲できる。Mock作成中に製品コード、DB、依存関係、API、権限、設定を変更しない。

## 開始条件／入力

依頼内容、対象ユーザー操作、既存画面、既存コンポーネント、スタイル、デザイントークン、画像素材、対応端末、01で調査した対象範囲を入力とする。

## 使用中のUIライブラリを把握する

Mockを作る前に、推測ではなく現在のコードから次を調査し、計画HTMLとplan.mdへ記録する。

- `package.json`と対象workspaceの`package.json`にあるUI・CSS・アイコン・日付・フォーム関連の依存関係
- 対象画面が実際にimportしているUIライブラリと共通コンポーネント
- theme、色、文字、余白、角丸、影、ブレークポイントなどの既存定義
- 利用できる画像、アイコン、ロゴと、その利用条件
- desktop／mobileなど、受入確認が必要な表示幅

依存関係に存在するだけで実際には使われていないライブラリを採用しない。Mockのために新しいUIライブラリを追加しない。

## 手順

1. 対象機能の利用開始から完了までの画面と状態を洗い出す。
2. 使用中のUIライブラリ、共通コンポーネント、デザイントークンを調査する。
3. 実装AIが既存部品で再現できるよう、使用部品、文言、配置、寸法、余白、色、状態、操作後の変化、表示幅を具体化する。
4. 既存UIと同じライブラリ・共通部品・デザイントークンを使ったMockを作る。製品コードへ組み込まず、Mock作成用の一時成果物として扱う。
5. 必要な各状態と表示幅をPNGへ書き出す。1枚で表せない場合は、状態または表示幅ごとに複数のPNGを作る。
6. PNGと再現条件を計画HTMLとplan.mdから参照し、人間の承認対象に含める。

## 完全再現の条件

実装担当が見た目を推測しなくてよいように、少なくとも次を確定する。

- 使う既存コンポーネントまたはUIライブラリの部品名
- 表示する文言、アイコン、並び順
- 幅、高さ、余白、配置、色、文字サイズ、角丸
- 通常、選択、入力中、空、読込中、成功、エラー、無効のうち機能に必要な状態
- 押下、入力、閉じる、戻るなどの操作と、その直後の表示
- desktop／mobileのうち対象となる表示幅

PNGに表せない操作や状態遷移は、計画HTMLとplan.mdの再現条件に文章で記録する。PNGだけを見て実装者に推測させない。

## 成果物の配置と名前

最終成果物はPNGとする。runがある場合でも`human/images/`へ置き、次の名前を基本とする。

```text
mock-<feature>-<viewport>-<state>.png
```

例：`mock-group-invite-mobile-default.png`。runがない小規模作業では、計画担当がGit管理される人間向け画像置場を指定し、計画または引継ぎに絶対パスではなくリポジトリ相対パスを残す。

## 禁止事項

- Mockだけのための依存追加
- 存在しないUIライブラリやコンポーネントを使った前提
- 製品コード、DB、API、権限、設定の変更
- PNGにない部分を実装担当の推測に任せること
- 秘密情報、実在する個人情報、本番データをMockへ含めること
- 承認前にMockを製品UIとして実装すること

## 完了条件

- 実行条件に該当することを01で確認済み
- 使用中のUIライブラリと既存部品をコードから確認済み
- 必要な画面、状態、表示幅を表すPNGがある
- PNGと再現条件が計画HTMLとplan.mdから参照されている
- 実装担当が新しい判断をせず、既存ライブラリと共通部品で再現できる
- 人間がPNGを含む計画を承認できる状態である

## 失敗時／差戻し

既存部品だけでは要求を再現できない、新しい依存が必要、UI仕様が決められない、または対象状態が不足している場合は計画担当へ返す。新しい依存や仕様変更が必要なら、01の計画HTMLとplan.mdへ具体的な変更を追加し、承認前に解決する。
